# MEDP-002 Candidate Evaluation Methodology

## Purpose

MEDP-002 selects the first official Market Edge Discovery Program construct through transparent scientific prioritization. It does not start construct research, define indicators, implement code, validate performance, claim alpha, or recommend deployment.

## Candidate Universe

The evaluated P1 candidates are fixed before scoring:

- Time-Series Momentum
- Cross-Sectional Momentum
- Value
- Profitability / Quality
- Post-Earnings Announcement Drift (PEAD)

No P2 candidates were evaluated because the P1 universe was sufficient to select a first candidate.

## Source Inputs Used

- User-provided MEDP-002 candidate list.
- Existing LR-001 Momentum and Relative Strength Literature Review.
- Existing RC-E1 evidence synthesis from production-strategy research.
- Existing CPP-008 final construct ecosystem review.
- Existing construct research operating framework.

## Source Limitation

Repository search did not locate explicit MEDP-000 Candidate Catalog or MEDP-001 Constructability Framework files. Therefore MEDP-002 records this as a provenance limitation and reconstructs the scoring framework from the user-provided MEDP-002 specification and existing project evidence.

## Weighting Freeze

Raw criterion weights were specified and then normalized to sum to exactly `1.00` before scoring. The normalized weights in `weighted_scoring_framework.csv` are the operative frozen weights. Raw weights are retained for auditability.

## Scoring Scale

Each criterion is scored from 1 to 5:

- 5 = very strong / highly favorable
- 4 = strong / favorable
- 3 = moderate / acceptable
- 2 = weak / problematic
- 1 = very weak / major blocker

## Decision Rule

The highest weighted-score P1 candidate receives GO if it has no fatal constructability or look-ahead-safety blocker. Other candidates receive WAIT, LOW PRIORITY, or REJECT according to scientific readiness.

## Boundary

Scores are prioritization judgments, not evidence of alpha, profitability, or production value.
